Kotlin Nullability
Kotlin distinguishes between nullable (String?) and non-nullable (String) types, forcing you to handle potential nulls explicitly. Use the safe-call operator (?.) to safely access properties that might be null, the Elvis operator (?:) to provide default values when something is null, and traditional if/else null checks for smart casting to non-nullable types. Avoid the not-null assertion (!!) unless absolutely necessary, as it defeats Kotlin's null-safety by throwing a NullPointerException if the value is null. The philosophy is simple: handle nulls gracefully with safe operators, not with crashes.
